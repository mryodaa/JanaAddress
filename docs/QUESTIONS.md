# Открытые вопросы к организаторам

Для каждого вопроса записан вариант, который выбран сейчас: самый безопасный для метрики (null лучше неверного значения). Когда придут ответ или `sample_output.json`, правим код и вычёркиваем вопрос.

| # | Вопрос | Что сделано сейчас | Где в коде |
|---|--------|--------------------|-----------|
| Q1 | Форма контейнера во входе и выходе: массив, объект с ключом, JSONL? Слайд показывает только одну запись. | Принимаем всё. Ответ повторяет форму входа (массив → массив, `{"records": [...]}` → тот же ключ, прочие ключи верхнего уровня сохраняются, JSONL → JSONL). | `src/jana_address/io_format.py` |
| Q2 | `sample_input.json`, `sample_output.json`, `train.json` пока не выданы. | Работаем по слайду «Формат» и ТЗ. Собственные фикстуры лежат в `tests/fixtures/`. Ожидания сверим с `sample_output.json`, когда он появится. | `tests/fixtures/` |
| Q3 | Невидимые символы (U+200B, NBSP...) внутри street_name/landmark: оставлять, как в строке, или чистить? Метрика удаляет только пунктуацию и пробелы. | Значение режем из оригинала по спану, потом удаляем zero-width/soft hyphen и превращаем NBSP в пробел. Больше ничего в значении не меняем. | `pipeline/extract.py` |
| Q4 | Точность группы полей считается пулом (все сравнения группы вместе) или средним по полям? | В `scripts/eval.py` основной итог считается пулом, рядом печатается вариант со средним. | `scripts/eval.py` |
| Q5 | Если в эталоне null, а мы вернули значение (house, apartment и т.п.), это ошибка? По ТЗ такая запись не входит в метрику. | По умолчанию не считаем. Флаг `--strict-fp` считает такое ошибкой, для честной внутренней оценки. | `scripts/eval.py` |
| Q6 | ЖК / микрорайон без отдельной улицы: правило ТЗ для микрорайона это street_type=«микрорайон». Для ЖК без улицы тоже street_type=«жилой комплекс»? | Да, одно правило для всех «площадных» типов (мкр, квартал, ЖК, жилой массив): без улицы идёт в street_type/street_name, с улицей в living_area. | `pipeline/street.py` |
| Q7 | landmark включает предлог? «напротив школы 5» → «напротив школы 5» или «школы 5»? | Берём «как написано», вместе с предлогом. | `pipeline/landmark.py` |
| Q8 | «Абая 150-23» → house 150, apartment 23? | Да (типичная запись дом-квартира). Правило отключается в `rules/markers.yaml` (`house_dash_apartment`). | `pipeline/numbers.py` |
| Q9 | city/province/district отдаём в каноническом виде справочника («Ақтөбе қаласы» → «Актобе») или как в строке? | Канонический русский вид из справочника. Если в справочнике нет, отдаём строковое значение без служебных слов. | `pipeline/admin.py` |
| Q10 | Корпус / строение («дом 5 корпус 2», «11к2», «стр. 1», «блок С»): входят в house? Офис / бутик / павильон / кабинет / помещение: это apartment? | **Решено с командой: корпус сохраняем в house как написано**: «5 корп 2», «11к2», «30/1 стр. 2», «58 корпус Б» (срез строки от начала дома до конца корпуса, шаг `building`). Только если корпус идёт сразу за номером дома (через пробел, запятую, точку или слитно); «5 кв 10 корп 2» -> house «5». Дома в строке нет («ЖК Хайвил, блок С»): house = корпус (при null в эталоне в метрику не входит, Q5). Номер корпуса никогда не становится квартирой. Поиск дома в справочнике с корпусом откатывается на номер без него (район тот же). Нежилые помещения (офис, бутик, павильон, кабинет, помещение, склад, бокс) считаем apartment. | `pipeline/parts.py` (`Parts`, `AttachBuilding`), `reference/store.py` (`house`) |
| ~~Q11~~ | ~~Docker на машине разработки не установлен.~~ | Закрыт: Docker установлен, `docker build --no-cache --network=none` проходит, контейнер healthy за ~6 с. | `Dockerfile` |
| Q12 | Литера через пробел «12 А»: в эталоне «12 А» или «12А»? Метрика удаляет пунктуацию, но не пробелы: «12-а» = «12а», а «12 а» ≠ «12а». | По ТЗ «как есть»: отдаём «12 А». Дефис и пробелы вокруг дроби (`1 / 2` → `1/2`) убираем. | `pipeline/util.house_value` |
| Q13 | district из строки отдавать как написано («Есильский») или в канонической форме справочника («Есиль»)? | Русское написание из строки берём как есть (без слова «район»). Казахское и латинское («Іле ауданы») переводим в каноническое русское («Илийский»). | `pipeline/admin.py` |
| Q14 | Районы Астаны: эталон «Есиль» или «Есильский»? | Каноническое значение справочника «Есиль» (официальное название «район Есиль»). Прилагательные записаны как алиасы. | `seed/admin.yaml` |
| Q15 | Если в строке нет города, но есть район города («Турксибский район, ...»), считается ли «Алматы» в эталоне city «из строки»? | Восстанавливаем city/province по справочнику: если жюри это считает, получаем балл, если нет, метрике это не вредит. | `pipeline/reference_step.py` |
| Q16 | Кодировка входного файла: только UTF-8? Файл, сохранённый в Excel/Блокноте Windows, бывает в cp1251 или UTF-16. | Принимаем UTF-8 (с BOM и без), UTF-16 по BOM, иначе cp1251, чтобы не отклонять весь батч. Ответ всегда UTF-8. | `io_format.decode` |
| Q17 | Соглашения посимвольной разметки теггера (не формат жюри, но влияет на то, что модель предлагает). | Город, область, район: только название без маркера («г.», «область», «район» это O). Маркер улицы и маркер площадного типа без улицы: STREET_TYPE; мкр с отдельной улицей: название LIVING_AREA, маркер O. Казахская половина двуязычной записи целиком (`/Ақтөбе қаласы`): KZ_DUP. Телефоны, индексы, ФИО, «Казахстан», «Адрес:», служебные хвосты: NOISE. Ориентир вместе с предлогом (как Q7). В «150-23» дефис O. Значения полей из спанов строит арбитр по тем же правилам, что и шаги правил (Q3, Q9, Q12, Q13). | `scripts/synth/builder.py`, `pipeline/arbiter.py` |
| Q18 | Прежняя область после передела («ВКО, г. Семей», «Алматинская обл., Талдыкорган», «Карагандинская обл., Жезказган»; 2022: Абайская, Жетысуская, Улытауская): в эталоне область как написано или нынешняя? | Как написано (каноническое имя прежней области): province берётся из строки, а справочное значение строковое не перезаписывает. Такая пара не считается конфликтом и не понижает confidence. Если в эталоне нынешняя область, переключатель в одном месте: `rules/admin.yaml`, `historical_provinces` + `pipeline/reference_step.py`. Если в строке области нет, восстанавливается нынешняя. | `rules/admin.yaml`, `pipeline/reference_step.py` |
| Q19 | Строка набрана в английской раскладке вместо русской («Fkvfns ek f,fz 150» = «Алматы ул абая 150»): что отдавать в street_name? Срез «как есть» дал бы «f,fz». | Перекодируем посимвольно (клавиша QWERTY -> ЙЦУКЕН, длина та же) и разбираем перекодированную строку; street_name = срез перекодированной строки («абая»). Только если в строке нет кириллицы и после перекодировки узнаётся хотя бы два слова, а до неё заметно меньше (латинский «Almaty, ul. Abaya» не трогается). Флаг `layout_fixed` понижает confidence. id и raw_address в ответе исходные. | `pipeline/layout.py` |
| Q20 | Улица проходит через несколько районов / мкр, а дома в справочнике нет: ставить ли district / living_area? | Ставим лучшего кандидата по доле домов (или длины сегментов, если домов < 3), неуверенность только во флаге `district_ambiguous` / `living_area_ambiguous` и пониженном score (решение команды, 2026-10-17). Отступление от «null лучше неверного» безопасно для метрики: district/living_area из справочника входят в неё, только если написаны в строке, а при значении в эталоне null тоже ошибка. Порог доминирования 0.8 в одном месте: `pipeline/reference_step.py` (`DOMINANT_SHARE`). | `pipeline/reference_step.py` |
