# Справочник адресов

Справочник собирается нашими скриптами из открытых источников в один файл `reference/reference.sqlite`, который кладётся в образ. Сеть и тяжёлые зависимости (pyosmium, shapely, openpyxl) нужны только при сборке; вся геометрия и пространственные вычисления делаются там же, а в файл попадают готовые таблицы привязок. Рантайм делает только поиск по индексам SQLite, без shapely и без геометрии, и в интернет не ходит. Строки из `train.json` никуда не отправляются и в справочник не попадают: там только топонимы.

## Источники и лицензии

| Источник | Что берём | Лицензия / атрибуция |
|----------|-----------|----------------------|
| **Ручное ядро** `scripts/build_reference/seed/admin.yaml` | 17 областей и 3 города республиканского значения в формате ответа, районы городов респ. значения и части областей, областные центры и крупные города, микрорайоны Алматы; алиасы рус/каз/лат и старые названия | собрано командой по общедоступным сведениям об АТД РК |

## Как собрать заново

```bash
pip install -e ".[build]"                                       # osmium, shapely, openpyxl
python scripts/build_reference/download.py osm                  # ~220 МБ, с докачкой
python scripts/build_reference/osm_survey.py                    # -> docs/OSM_SURVEY.md (разведка, ~3 мин)
python scripts/build_reference/osm_extract.py                   # -> cache/osm_raw.jsonl (~3 мин, 390 МБ)
python scripts/build_reference/assign_districts.py              # -> cache/osm_assigned/ (вся геометрия, ~1 мин)
python scripts/build_reference/download.py kato --url <ссылка на xlsx со страницы КАТО stat.gov.kz>
python scripts/build_reference/kato.py cache/kato.xlsx          # -> cache/kato.json
python scripts/build_reference/build_sqlite.py --osm scripts/build_reference/cache/osm_assigned \
       --kato scripts/build_reference/cache/kato.json           # -> reference/reference.sqlite + coverage.json
python scripts/build_reference/gen_landmarks.py                 # -> src/jana_address/rules/landmarks_osm.yaml
```

Без OSM и КАТО `build_sqlite.py` собирает справочник из одного ядра: сервис работает, но без улиц и домов. Порядок слияния ядро → OSM → КАТО задаёт приоритет канонического написания: ядро, затем русские `name:ru` OSM («Весёлая Роща»), затем КАТО (в нём часть русских названий записана казахскими буквами: «Аққулы»). КАТО дописывает коды, районы пунктов без района и пункты, которых нет в OSM (`source=kato`).

Синтетические dev/отложенные наборы и данные теггера собраны со снапшота `reference/reference.synth_v1.sqlite` (`config.SYNTH_DB`, не в git и не в образе): пересборка основного файла не сдвигает их воспроизводимость и разбиение unseen.

## Что берётся из OSM

Разведка дампа: [docs/OSM_SURVEY.md](OSM_SURVEY.md) (`osm_survey.py`, тот же отбор, что у `osm_extract.py`).

* **Уровни admin_level определяются по данным** (`osm_common.detect_levels`), не хардкодом: область = самый мелкий уровень, где ≥ 14 полигонов (в дампе 4); город респ. значения = полигон этого уровня меньше 5000 км²; район области = уровень, где больше всего полигонов «... район/ауданы» вне городов (6); районы города = для каждого города респ. значения и каждой городской администрации («Г.А.», «қ.ә.») уровень не мельче контейнера, где внутри больше всего полигонов с маркером района (Алматы, Астана, Шымкент: 6; Актобе: 6 рядом с «Актобе Г.А.»; Тараз: 7). Сельские округа («с.о.», «... сельский округ», 8-й и 10-й уровни) районами не считаются.
* **Населённые пункты:** `place=city/town/village/hamlet/isolated_dwelling` точками; контуры: `place`-полигоны и admin-границы глубже района, если внутри нет других пунктов (иначе это сельский округ, названный по главному селу, и он «забрал» бы улицы соседей).
* **Мкр/ЖК:** полигоны `place=suburb/neighbourhood/quarter/city_block/allotments` и `landuse=residential` с name (тип «жилой комплекс»), точки тех же `place` без полигона.
* **Улицы:** `highway` с name (16 классов), линия целиком; название делится на тип и имя по `rules/street_types.yaml` (рус и каз: улица/көшесі, проспект/даңғылы, переулок/тұйық көше, микрорайон/шағын ауданы/ықшам ауданы, бульвар, шоссе, тупик, проезд, квартал...). Однобуквенные сокращения («у», «ш») с краю имени не снимаются.
* **Дома:** узлы и здания с `addr:housenumber` + `addr:street` или `addr:place` (центроид); `addr:place`, равный имени самого села, улицей не считается.
* **Объекты-ориентиры:** `shop=*`, `amenity=school/kindergarten/hospital/clinic/pharmacy/post_office/marketplace/bank/university/college/fuel`, `office=post` с name или brand.
* **Алиасы** всех сущностей с языком в `aliases.lang`: `name`, `name:ru` (ru), `name:kk` (kk), `name:en` (en), `old_name`, `old_name:ru/kk` (old), `alt_name*` (alt), `official_name*`, `short_name*`, `loc_name`.

## Как считаются привязки (assign_districts.py)

| Привязка | Как | Порог / правило |
|---|---|---|
| пункт → область, район области | точка в полигоне (shapely STRtree) | нет попадания: ближайший полигон района ≤ 2 км (`district_method=near`) |
| дом → город | полигон города респ. значения → контур пункта (самый мелкий) → ближайший пункт в радиусе | город 12 км, посёлок 5 км, село 2.5 км, хутор 1.5 км; `addr:city` уточняет, если такой пункт есть в 20 км |
| дом → район города | точка в полигоне района своего города | |
| дом → мкр/ЖК | самый мелкий содержащий полигон; мкр/квартал важнее ЖК (ЖК часто внутри мкр) | нет полигона: ближайшая точка мкр: neighbourhood/quarter/allotments 500 м, city_block 300 м, suburb 1200 м; `la_method=point`, `la_dist_m` |
| улица → районы и мкр | длина сегментов внутри полигонов + число домов | доля по домам, если домов ≥ 3, иначе по длине; доминирующий кандидат и доля в `streets.dom_*` |
| тип улицы | сегменты одного имени в городе склеиваются, у каждого типа своя длина | сегменты без типа сливаются в доминирующий по длине тип; `type_share` |
| мкр/ЖК → город, район | representative point полигона / точка | |
| объект → город, район, мкр | точка | |

При слиянии в `build_sqlite.py` улицы склеиваются по переводам имени (`name:ru` / `name:kk` / `name:en`: «Абай даңғылы» = «проспект Абая»), но не по старым и альтернативным именам: старое имя одной улицы бывает текущим у другой («Бердибай», бывшая «Толе би»). Доли районов пересчитываются после слияния. Одноимённые сёла одной области в разных районах (два «Акжара») остаются разными сущностями; выбирают между ними район и улица записи (`admin._prefer`, арбитр). Районы ядра, КАТО и OSM сливаются по ключу без «район», мягкого знака и окончания прилагательного (`district_key`: «Аксуатский» = «Ақсуат»).

## Использование в рантайме (`pipeline/reference_step.py`)

Заполняются только пустые поля; строковое значение не перезаписывается никогда. Источник поля в explain и UI:

| source | значит | подпись в UI |
|---|---|---|
| `reference:osm:house` | дом найден в справочнике: его район и мкр | справочник · OSM · дом |
| `reference:osm:street` | улица: доминирующий район/мкр, тип улицы, город по уникальной улице | справочник · OSM · улица |
| `reference:osm:polygon` | пункт → район области и область, мкр → район, район → город | справочник · OSM · полигон |
| `reference:osm:point` | мкр дома по ближайшей place-точке | справочник · OSM · точка |
| `reference:osm:poi` | район по ориентиру, однозначно найденному в городе | справочник · OSM · ориентир |
| `reference:seed`, `reference:kato` | табличная привязка ядра / КАТО | справочник · SEED / KATO |

Порядок уверенности для district / living_area: дом найден → его район и мкр; иначе улица → доминирующий район и мкр (**лучший кандидат и при неоднозначности**, доля < 0.8 даёт флаг `district_ambiguous` / `living_area_ambiguous` и пониженный score, см. Q20); мкр из строки → его район; населённый пункт → район области; улицы нет, а ориентир однозначно найден среди объектов города → его район с низким весом (`district_by_landmark`). Дом ищется сначала на улице написанного типа, потом на одноимённых другого типа (в OSM дома «Орал» без типа висят на одной из них). `street_type` без маркера: тип улицы из справочника; несколько одноимённых типов → доминирующий по длине, если его доля ≥ 0.6 (`street_type_dominant`). Старые названия улиц ищутся, только если по текущим совпадений нет.

`reference/store.py` держит в памяти только сущности и индекс алиасов (старт ≈ 0.6 с); дома, доли улиц по районам/мкр, объекты и метод привязки пункта запрашиваются лениво по индексам. Старая схема (без `street_areas`/`pois`) тоже читается.

Сетевые бренды из объектов (≥ 3 городов или ≥ 10 объектов, ≥ 4 букв, не автосалоны, без совпадений с топонимами и маркерами) генерирует `gen_landmarks.py` в `rules/landmarks_osm.yaml`; `rules_loader` сливает их с ручным `landmarks.yaml` (42 бренда: Halyk Bank, Kaspi.kz, Qazaq Oil, Гелиос, Спортмастер...).

## Схема `reference.sqlite`

`provinces`, `districts` (kind: oblast | city), `cities` (kind: republican | city | town | village; `district_method`: polygon | near | seed | kato), `living_areas`, `streets` (+ `length_m`, `houses`, `type_share`, `dom_district_*`, `dom_area_*`), `street_districts` и `street_areas` (дома, длина, доля), `houses` (номер, ключ, район, мкр, `la_method`, `la_dist_m`), `pois` + `poi_aliases`, `aliases` (etype, eid, alias, fold-ключ, язык, источник), `meta`. Схема: `scripts/build_reference/schema.sql`.

### Восстановление полей на отложенных наборах (`scripts/coverage_report.py`)

Доля записей, где поле заполнено, и сколько из них восстановлено по справочнику. «До» = тот же код на старом справочнике (снапшот 16.10), «после» = ядро + OSM + КАТО. Эталон для этого не нужен; качество восстановленных значений меряет `eval.py` (справочные поля входят в метрику, только если написаны в строке). `train.json` не выдан, на нём не прогонялось.

После слияния (ключ `district_key`) не сошлись: OSM «Ойылский» / КАТО «Уилский» (Актюбинская, переименование), OSM «Кызылкогинский» / КАТО «Кзылкогинский» (Атырауская), КАТО «Казыбек би» и «Алихана Бокейханова» (районы Караганды: полигонов в OSM нет). ## Ограничения покрытия

* Районы внутри города в OSM есть только у Алматы, Астаны, Шымкента, Актобе и Тараза. У Караганды районы есть в ядре и КАТО, но без полигонов: district по дому там не восстанавливается.
* В сёлах OSM часто нет улиц и домов: район области и область восстанавливаются по самому пункту (полигон или КАТО), улица и дом остаются как в строке.
* Мкр по точке (`osm:point`) приблизителен: у Павлодара, Петропавловска, Усть-Каменогорска большая часть мкр домов найдена так.
* Привязка по геометрии честнее старых связей, но иногда расходится с привычным написанием: сёла, вошедшие в новый город Алатау (Али), в OSM лежат внутри его полигона, и их улицы теперь относятся к Алатау.

При сборке отсеиваются мусорные значения OSM: целые адреса в `addr:street` и в именах объектов (запятые, индексы, «дом 28 кв.12», длиннее 60 символов). В справочнике остаются только топонимы, это проверяет `tests/test_no_memorization.py`.
