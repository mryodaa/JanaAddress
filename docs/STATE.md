## 1. Задача в двух словах

Хакатон Jana Post x Terricon Valley, кейс «Jana Address». Вход: JSON с записями `{id, raw_address}`, одна строка адреса Казахстана (рус/каз/латиница, мусор, опечатки). Выход на каждую запись: `id`, `raw_address` (байт в байт), 11 полей `province, city, district, living_area, street_type, street_name, house, apartment, entrance, floor, landmark` и `confidence` в [0, 1]. Неизвестное поле = `null`.

Метрика жюри (реализована в `scripts/eval.py`): per-field сравнение после lower + удаления пунктуации + схлопывания пробелов.
* адрес 60%: `province, city, street_name, house`;
* детали 25%: `apartment, entrance, floor`;
* справочные 15%: `district, living_area`, только если значение есть в строке (`_from_reference` в эталоне).
* Поле, где в эталоне `null`, в метрику не входит (Q5), поэтому **null лучше неверного значения**. `street_type` и `landmark` вне метрики, но выводятся.

Ограничения: офлайн рантайм, без LLM/геокодеров, 1000 записей < 5 мин (у нас ~1 с), запрет на запоминание train.json (матчинг по id, кэш по целой строке).

**Данных от организаторов ещё нет**: `train.json`, `sample_input.json`, `sample_output.json` не выданы. Всё качество измерено на собственной синтетике (раздел 6).

### Пайплайн (`pipeline/steps.py`, снимок 2026-10-16: актуальный порядок шагов в разделе 000 и docs/ARCHITECTURE.md)

Шаги общаются только через `ParseState` (`pipeline/base.py`): `raw` (не меняется), `text` (очищенный) + `offsets` (text → raw), `tokens` (`kind`: word/num/sep/punct, `used_by`: кто забрал токен, `glued_left`), `fields` (`FieldValue`: value, source, span в raw, score), `flags` (для confidence), `ref_ids` (id сущностей справочника, найденных по ходу: city, province, district, street_end), `trace`.

`ParseState.set_field` гарантирует: пустое значение не пишется, существующее не перезаписывается без `overwrite`, строковое (`source="string"`) никогда не перезаписывается справочным.

| # | Шаг | Файл | Суть |
|---|---|---|---|
| 1 | clean | `clean.py` | убирает невидимые (U+200B/C/D, U+2060, FEFF, soft hyphen), управляющие; NBSP → пробел; NFC; карта смещений |
| 2 | tokenize | `tokenize.py` | регулярка num/abbr/word/sep/punct; `12а`, `12-а`, `1/2`; литера через пробел `12 А` (HOUSE_LETTERS, без д/к/п/с/т/у/ш/и); `47Бдом` → `47Б`+`дом`; порядковые `1-я` → word; ` / ` как разделитель (тогда дробь только слитная); `mark_service_numbers`: телефоны, индексы (6 цифр), время → `noise:*` |
| 3 | split_bilingual | `bilingual.py` | «Актобе/Ақтөбе қаласы»: казахская половина → `kz_dup` (по каз. буквам и маркерам; `қ`, `обл`, `ауд` тоже закрывают половину) |
| 4 | admin | `admin.py` (366 строк) | область (маркер + словарь, ВКО/ЗКО/СКО), город (префикс/суффикс маркера, посёлок/село, город без маркера в начале сегмента), район (`район`, `р-н`, `ауданы`, но не «шағын ауданы»). Город без маркера, совпадающий с улицей (`ambiguous_city_keys`), берётся только если дальше улица этого города или номерной мкр/квартал |
| 5 | details | `details.py` | дом/кв/подъезд/этаж по `markers.yaml`; слитные `11дом`, `кв70`; ориентация (маркер до/после числа); `needs_dot` (однобуквенные только с точкой), `needs_number` (`п.` только перед числом = подъезд) |
| 6 | street | `street.py` (370 строк) | тип улицы до/после названия (`POSTFIX_FOLDS` для каз. «көшесі», «шағын ауданы»); площадные типы (мкр, квартал, ЖК, ж/м...) забирают номер в название; мкр без улицы → street_type/street_name, мкр + улица → living_area; `_guess`: улица без маркера = группа слов перед номером/домом по маркеру (флаг `guessed_street`); инициалы «Ш. Мыкитанулы»; `Самал-3 40`; «Сыргак батыр 3, 11дом» |
| 7 | landmark | `landmark.py` | предлоги (напротив, возле...), объекты (магазин, ТЦ, школа...), бренды (Qazpost, Magnum...) из `landmarks.yaml`; номер только после нумеруемых объектов; несколько кусков склеиваются, только если между ними одни разделители |
| 8 | numbers | `numbers.py` | дом/кв по позиции: первое свободное число после улицы → house, `150-23` → house+apartment (Q8), следующее → apartment; лишние → флаг `extra_numbers` |
| 9 | leftover | `leftover.py` | населённый пункт без маркера отдельным сегментом перед улицей («Илийский район, Боралдай, ул. ...») |
| 10 | reference | `reference_step.py` | только пустые поля: город → область; район → город; мкр → город/район; улица (+дом) → город (если улица уникальна), тип, район (дом в справочнике → его район, иначе доминирующий ≥ 80%, иначе null + `district_ambiguous`) |
| 11 | confidence | `confidence.py` | base 0.35 + 0.30·доля разобранных токенов + бонусы за поля − штрафы за остаток и флаги (`confidence.yaml`), × (0.75 + 0.25·min score строковых полей), clip [0.02, 0.99] |

`runner.parse_record`: пустой/нестроковый `raw_address` или исключение → все поля null, confidence 0, батч не падает. `?explain=true` / `--explain` добавляет `fields` (source, span), `trace`, `unparsed`.

## 4. Незакоммиченные правки (рабочая копия, 22 файла, +450/−59, плюс 3 новых файла)

Сделаны в последней сессии по ошибкам на синтетике. Все тесты зелёные.

* **Инструменты оценки**: новые `scripts/gen_dev.py` (синтетический dev-набор с `_tags`, режим `--chaos`), `scripts/fuzz.py`, `tests/test_fuzz.py`; `eval.py` получил разбивку по тегам и `--baseline OLD_PRED.json` (что исправлено / сломано).
* **tokenize**: служебные числа (телефон, индекс, время) → `noise:*`; ` / ` как разделитель; порядковые числительные как слово; литера, слипшаяся с маркером (`47Бдом`); расширен набор литер через пробел и литера перед маркером детали (`12 А кв 4`).
* **base.orig_span**: комбинирующие диакритики после NFC входят в спан.
* **bilingual**: `қ`, `обл`, `ауд` закрывают казахскую половину.
* **admin**: город без маркера, совпадающий с улицей, подтверждается улицей этого города или номерным мкр/кварталом; площадной тип с номером после города не мешает городу; чужой маркер обрывает имя города; `city` как суффикс («Almaty city»).
* **details**: `needs_number` (`п. 9` = подъезд, `п. Береке` = посёлок).
* **street**: инициалы в названии, латиница в названиях ЖК, номер через дефис (`Самал-3`), номер в названии при доме по маркеру, `66квартал 12`, `_guess` принимает дом по маркеру и улицу после города в своём сегменте; «шағын аудан» без -ы.
* **landmark**: значение всегда один непрерывный спан исходной строки.
* **io_format.decode**: UTF-16 по BOM, fallback cp1251 (Q16).
* `build_sqlite.py`: индекс `\b\d{6}\b` (не отсеивать топонимы с 6 цифрами внутри).
* `test_no_memorization.py`: значения справочника читаются потоком (иначе не хватало памяти).
* Документы: README (раздел о синтетике, таблица результатов), ARCHITECTURE (tokenize), QUESTIONS (Q11 закрыт, Q16 добавлен), CLAUDE.md (команды gen_dev/fuzz/--baseline).

## 7. Известные слабые места (по ошибкам отложенного хаоса)

Худшие теги: `settlement` / `city_kind:village` ~80% записей верны целиком, `house_letter` ~86%, `no_commas` ~88%, `district_written` ~88%, `area_with_street` ~87%, `case_upper/lower` ~89%.

1. **Населённый пункт без маркера** (главный источник ошибок province/city): город в конце строки или в середине без запятых («ул Кенесары Касымова 139 Ерейментау», «Бесагаш Айтеке би, 68», «Акколь ул ...», «тел ... - Уральск - квартира 234») не находится; одноимённые сёла дают неверную область («п. Белоусовка» → Павлодарская вместо ВКО, «п. Аксу» → Павлодарская вместо Туркестанской): нет выбора по району/улице, когда в строке есть район или улица, известная только в одном из одноимённых сёл.
2. **Многословные и номерные названия улиц**: «2-й проезд Рахимова», «4 переулок Садовой», «Н.Торекулво 3 тупик», «Талды Су», «2-ші шағын аудан», «ул. Коммунальный пер» режутся или теряют часть.
3. **Мусор перед улицей без маркера** попадает в название: «Казахстан Борили», «Kazakhstan - 24», «Бесагаш Айтеке би» (город склеивается с улицей).
4. **Литера через пробел перед маркером** «17 Адом», «181 д дом», `58-адом`.
5. **landmark захватывает хвост**: ФИО, «тел», «доставка курьером», «оставить у двери», «для Нурлана», город после ориентира. Нужен стоп-список «служебных хвостов» и обрыв по ФИО (`Фамилия И.И.`, `Ахметов Б.`).
6. **street_type не восстанавливается** для улицы без маркера, если в справочнике у неё нет однозначного типа (вне метрики, но видно в UI).
7. Номер в названии без маркера дома путается с домом: «ДСУ-115, 4», «40 лет Победы 31 подъезд 9», «с. 30 лет Казахстана, мкр 33 36».
8. Корпус / блок не входят в house (Q10), КАТО нет, районов у большинства областных центров нет.
