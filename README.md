# Jana Address

Сервис разбора однострочных адресов Казахстана на поля `province, city, district, living_area, street_type, street_name, house, apartment, entrance, floor, landmark` с осмысленным `confidence`. Район, жилой массив, город и область, которых нет в строке, восстанавливаются по собственному справочнику (OSM + КАТО + ручное ядро). Решение для хакатона Jana Post x Terricon Valley, кейс «Jana Address».

* правила и словари в YAML + справочник SQLite + посимвольный теггер (650 КБ, ONNX) с арбитром, без сетевых вызовов, LLM и геокодеров в рантайме;
* на каждую запись ровно один ответ, `id` и `raw_address` байт в байт, неизвестное поле = `null`;
* 1000 записей разбираются за 1–2 секунды вместе с моделью (требование: 5 минут);
* UI оператора: загрузка пакета, таблица с подсветкой, правка с клавиатуры, экспорт, trace по шагам.

## Запуск одной командой

```bash
docker compose up --build
# http://localhost:8000      — интерфейс
# http://localhost:8000/docs — OpenAPI
```

Healthcheck compose ждёт `GET /api/v1/health` (готовность наступает меньше чем через секунду после старта: справочник грузится при старте).

## Как жюри прогоняет тестовый набор

**Через батч-эндпоинт** (файл как есть: JSON-тело или multipart):

```bash
curl -s -X POST http://localhost:8000/api/v1/parse/batch \
     -H "content-type: application/json" --data-binary @data/sample_input.json > out.json
# или файлом
curl -s -X POST http://localhost:8000/api/v1/parse/batch -F file=@data/sample_input.json > out.json
# источники полей и trace (для разбора на защите)
curl -s -X POST "http://localhost:8000/api/v1/parse/batch?explain=true" -F file=@data/sample_input.json
```

Форма ответа повторяет форму входа: массив → массив, объект `{"records": [...]}` → тот же ключ, JSONL → JSONL (см. `docs/QUESTIONS.md`, Q1).

**Через CLI** (запасной путь, без сервера):

```bash
docker compose run --rm -v "$PWD/data:/data" jana-address python -m jana_address.cli /data/sample_input.json /data/out.json
# локально
python -m jana_address.cli data/sample_input.json out.json
```

## Пайплайн

`layout → clean → tokenize → split_bilingual → parts → admin → details → street → landmark → numbers → building → leftover → tagger → arbiter → reference → confidence`. У каждого шага единый интерфейс (`ParseState → ParseState` + trace) и свои тесты. Подробно: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Словари маркеров, типов улиц (с сокращениями, латиницей и казахскими формами), ориентиров и веса confidence лежат в `src/jana_address/rules/*.yaml`. Новый паттерн добавляется без правки кода.

## Гибридный разбор

Второй независимый разборщик: посимвольный теггер (char BiLSTM-CRF, около 600 тыс. параметров, ONNX int8, 650 КБ в
образе) и арбитр между ним и правилами. Модель видит контекст строки целиком (город без маркера в конце, улица без
маркера после села, строка без запятых), правила и справочник проверяют её предложения. По каждому спорному полю
оба кандидата проверяются справочником (город существует и согласован, улица есть в этом городе, дом на улице) и
грамматикой (этаж <= 40, подъезд <= 20); спорные поля решаются совместно, без пересечения спанов. Значение всегда
срез исходной строки или каноническая форма справочника: модель только показывает, где поле.

* Обучена только на синтетике из собственного справочника с сильными искажениями (`scripts/gen_train_tagger.py`);
  15% улиц и 10% населённых пунктов в обучение не попадали: на них проверяется обобщение (`unseen`).
* Рантайм без torch: onnxruntime + CRF на numpy, батчи по 256 строк. `JANA_TAGGER=off|shadow|on`.
  Нет модели или она упала: работаем на правилах, батч не падает.
* Решения арбитра по каждому полю видны в `?explain=true` (`model`) и во вкладке «шаги разбора» UI.

**Результаты** (`scripts/compare_modes.py`, полностью: [docs/hybrid_results.md](docs/hybrid_results.md)). Все наборы
отложенные: ни модель, ни веса арбитра на них не подбирались. Решение о включении принимается по первым трём.

| Набор | rules | tagger (только модель) | **hybrid** | ECE confidence rules → hybrid |
|---|---:|---:|---:|---:|
| dev_synth_s2 (2000) | 98.7% | 99.5% | **99.2%** | 0.035 → 0.014 |
| dev_chaos_holdout (3000) | 98.1% | 99.5% | **99.0%** | 0.036 → 0.010 |
| dev_chaos_v2_holdout (3000, новый seed) | 98.3% | 99.4% | **99.2%** | 0.039 → 0.011 |
| dev_hard_holdout (3000, сильные искажения) | 95.6% | 99.4% | **97.6%** | 0.030 → 0.016 |
| unseen (3000, улицы и пункты вне обучения) | 95.3% | 99.2% | **97.6%** | 0.038 → 0.014 |

Hybrid включён по умолчанию (`JANA_TAGGER=on`): на решающих наборах он выше правил, и ни одно поле метрики не
хуже. Модель отдельно на синтетике ещё выше, но эта цифра завышена сильнее всего: модель обучена на том же
генераторе. Hybrid сознательно консервативнее: модель меняет поле правил, только когда это подтверждают справочник,
грамматика и непротиворечивость записи. Слабое место: номерные улицы («2-й проезд Рахимова»), которых нет в
справочнике: арбитр оставляет вариант правил (40% против 97% у модели). Решающий набор после выдачи данных:
`data/dev_gold.json`.

Регламент: модель 650 КБ в образе, холодный старт со справочником и моделью около 1 с (контейнер healthy за 6 с
при `--network=none`), 1000 записей hybrid через API около 1.4 с (в контейнере 1.7 с), фаззинг hybrid 20 тыс. строк
без нарушений.


**Кривые данные, которые разбираются отдельно** (правила + модель обучена на них же):

* организации: «ТОО «Сапа Трейд»», «ИП Сериков», «АО …», «ЖШС …» не попадают ни в улицу, ни в ориентир;
* офис / бутик / павильон / кабинет / помещение / склад / бокс считаются квартирой (Q10);
* корпус / строение / блок сохраняются в доме как написано: «5 корп 2», «11к2», «30/1 стр. 2»; квартирой не становятся (Q10);
* число в начале названия улицы без маркера: «40 лет Победы 31», «9 Мая 10», «30 лет Казахстана 5»;
* прежняя область после передела 2022 года («ВКО, г. Семей»): как написано, без штрафа за «конфликт» (Q18);
* строка в английской раскладке («Fkvfns ek f,fz 150 rd 5» -> Алматы, ул. абая, 150, кв 5), Q19.

Подробно (архитектура, данные, арбитраж, переобучение): [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#гибридный-разбор-правила--посимвольный-теггер).

## Справочник

`reference/reference.sqlite` (75 МБ): ядро + OpenStreetMap + КАТО. 20 областей и городов респ. значения, 197 районов, 14 280 населённых пунктов (97% с районом области), 5 527 мкр/ЖК, 55 тыс. улиц, 1.18 млн домов (309 тыс. с районом, 427 тыс. с мкр), 34 тыс. объектов-ориентиров, алиасы рус/каз/лат/старые. Вся геометрия считается при сборке (`scripts/build_reference/`, pyosmium + shapely), в файле готовые привязки: дом → район и мкр, улица → доли по районам и мкр, доминирующий тип улицы, пункт → район области. Рантайм только ищет по индексам SQLite, без геометрии.

Восстановление на отложенных синтетических наборах (тот же код, старый справочник → новый): district 70–73% → 74–78% записей, living_area 20–26% → 31–37%, street_type +0.4–0.6 п.п.; у каждого восстановленного поля источник в explain и UI (`reference:osm:house | street | polygon | point | poi`, `reference:kato`, `reference:seed`). Покрытие по областным центрам, пороги и пересборка: [docs/REFERENCE.md](docs/REFERENCE.md), разведка дампа OSM: [docs/OSM_SURVEY.md](docs/OSM_SURVEY.md).

```bash
python scripts/coverage_report.py data/dev_chaos_holdout.json            # доля восстановленных полей по источникам
python scripts/coverage_report.py data/dev_chaos_holdout.json --db reference/reference.synth_v1.sqlite   # «до»
```

## Оценка

`scripts/eval.py` считает метрику жюри ровно по ТЗ: per-field сравнение после нижнего регистра, удаления пунктуации и схлопывания пробелов; веса 60/25/15; справочные поля только там, где они есть в строке. Печатает разбивку по полям, топ ошибок с исходными строками и калибровку confidence (ECE).

```bash
python -m jana_address.cli data/dev_gold.json out.json
python scripts/eval.py out.json data/dev_gold.json
python scripts/eval.py out.json data/dev_gold.json --baseline out_prev.json   # что исправлено / сломано правкой
python scripts/analyze_train.py data/train.json --unknown   # что добавить в словари
python scripts/label.py data/train.json data/dev_gold.json --n 300 --shard 0/3   # разметка командой
```

**Синтетический dev-набор**, пока нет размеченных данных: `scripts/gen_dev.py` берёт реальные топонимы из справочника (города, улицы, дома, мкр) и собирает строки с искажениями из реальных адресов: слитное написание, литеры и дроби, латиница, рус/каз через слэш, дубли города, район вместо города, опечатки маркеров, невидимые символы, ориентиры. Эталон известен по построению, в записи есть `_tags`, и `eval.py` печатает точность по каждому типу искажения.

```bash
python scripts/gen_dev.py --n 1000 --seed 1            # -> data/dev_synth.json
python scripts/gen_dev.py --n 2000 --seed 11 --chaos --out data/dev_chaos.json   # + мусор вокруг адреса
python -m jana_address.cli data/dev_synth.json out.json && python scripts/eval.py out.json data/dev_synth.json
```

`--chaos` добавляет то, что люди пишут в поле «адрес» помимо адреса: телефоны, индексы, ФИО получателя, «Казахстан»/«Адрес:», «до 18:00», опечатки и латиницу в названиях улиц, разделители ` / `, `|`, `;`, перемешанный порядок частей.

Это ориентир, а не независимая оценка: улицы берутся из того же справочника, что использует парсер (тег `street_unknown` даёт улицы не из справочника), шаблоны написаны нами. Проверять обобщение стоит на наборе с другим `--seed` и на живых строках, размеченных вручную.

| Набор | Итог | Комментарий |
|---|---|---|
| синтетика, seed 1 (1000) | 98.5% | на нём искали ошибки |
| синтетика, seed 2 (2000) | 98.7% | не смотрели при правках |
| хаос, seed 11 (2000) | 98.1% | на нём искали ошибки |
| хаос, seed 99 (3000) | 98.1% | отложенный, не смотрели; ECE confidence 0.039 |
| `tests/fixtures/dev_seed_gold.json` | 100% | кейсы из ТЗ |

**Почти реальный эталон** (train.json организаторы не выдают, `docs/QUESTIONS.md` Q21). Синтетика меряет нас нашими же шаблонами, поэтому в `data/realish/` собран эталон из источников, которые от генератора не зависят:

* **llm** — 607 строк «как клиент пишет адрес доставки»: префикс области/города из списка + свободный ввод (слитно, опечатки маркеров, латиница, казахский, повтор города, район вместо города, телефоны и просьбы курьеру). Написаны языковой моделью на этапе подготовки (слайд 11 это разрешает), топонимы «по памяти», не из нашего справочника;
* **egov** — 161 живая строка из адресных колонок открытых наборов data.egov.kz (школы, сады, аптеки, объекты): реестровый КАПС «Г.АЛМАТЫ, … ШУХОВА (УЛИЦА), 37Б», «ул., 9, -, -», «строение/ғимарат», казахский порядок «көшесі Адгам Каримов»;
* **team** — шаблон для ручного набора команды (`data/realish/team/team.txt`).

Разметка по слайду 08, не по выводу парсера; `scripts/realish.py validate` проверяет, что строковые значения есть в строке и нет служебных слов. Каждый набор делится по хешу id на `*_dev` (ошибки смотрим и правим) и `*_holdout` (только итог).

| Набор (hybrid) | до | после | Комментарий |
|---|---:|---:|---|
| llm_dev (310) | 97.2% | 99.3% | на нём искали ошибки |
| egov_dev (79) | 94.4% | 98.9% | на нём искали ошибки |
| **llm_holdout (297)** | 97.7% | **98.7%** | отложенный, один прогон |
| **egov_holdout (82)** | 95.4% | **98.2%** | отложенный (после переразметки по Q22 прогнан ещё раз) |
| dev_synth_s2 / dev_chaos_holdout / dev_chaos_v2_holdout / dev_hard_holdout | 99.2 / 99.0 / 99.2 / 97.6% | 99.4 / 99.2 / 99.4 / 97.8% | синтетика, отложенные; до перехода city на «как в строке» (эталон синтетики пишет город каноном) |

Что нашлось только на живых строках: повтор города в начале свободного текста, номерная улица после мкр («мкр Тураколь, ул 7 д 14»), многословные ЖК («ЖК Есентай парк»), «с.» с точкой как маркер села, село по старому названию из другой области, «ш.а.», перекрёсток («Шаляпина угол Саина»), реестровый формат «тип в скобках» и «РАЙОН (ГОРОД)», литера в кавычках, «строение N». Город и район отдаются как в строке: без перевода с казахского, опечатки, латиница и регистр как есть, срезается только служебное слово; область каноном справочника (Q22). Справочник нужен для привязки и для полей, которых в строке нет. Эталон синтетики пишет город каноном, поэтому city на синтетике ниже (~94–95%).

```bash
python scripts/realish.py lines data/realish/llm/*.txt --tag src:llm --prefix llm_ --out data/realish/llm.json
python scripts/realish.py validate data/realish/llm.json && python scripts/realish.py split data/realish/llm.json
python scripts/eval.py out.json data/realish/llm_dev.json --run hybrid
python scripts/build_reference/download.py egov            # адресные колонки data.egov.kz -> cache/egov/ (долго, докачивается)
python scripts/realish.py egov --out data/realish/egov/raw.txt --skip data/realish/egov/b*.txt   # новая пачка для разметки
```

**Надёжность.** `scripts/fuzz.py` гоняет пайплайн на случайном и «злом» вводе (мусор, эмодзи, HTML/SQL, 10 тыс. символов, управляющие и невидимые символы, порча реальных адресов) и проверяет: нет исключений и зависаний, `id`/`raw_address` не меняются, каждое строковое значение есть в исходной строке (ничего не выдумано), строка без букв и цифр даёт все поля null. 60 тыс. строк, нарушений 0; короткий прогон входит в `pytest` (`tests/test_fuzz.py`). Вход принимается в UTF-8, UTF-16 (по BOM) и cp1251 (Q16).
